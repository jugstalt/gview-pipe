# 26. Command line client

Date: 2026-11-02 · Status: accepted

## Context

The REST API ([ADR 0020](0020-rest-api.md)) is there for scripts and CI, but every pipeline has to wrap `curl` itself: ETags, the two-step deploy, waiting for a run and reading its result.

## Decision

- A .NET tool `gview-pipe` (`src/gView.Pipe.Cli`, package `gView.Pipe.Cli`, `dotnet tool install`) that only calls the REST API. It has no reference to the other projects and no dependency besides the framework (the command line is parsed by hand: a handful of commands and flags).
- One command per endpoint: `gview-pipe workflows list|get|export|deploy|delete|activate|deactivate`, `gview-pipe run <id>`, `gview-pipe executions list|get|cancel|replay`.
- **Connection:** `--url` / `PIPE_URL` and `--key` / `PIPE_API_KEY`. Keys are never stored in a file by the tool; the documentation recommends the environment variable because a key on the command line shows up in the process list.
- **Deploy:** takes files and folders (`*.json`, recursive). A workflow that exists is replaced with `If-Match` of the ETag the command just read, so a change made in the editor in between is not overwritten (`412` becomes a clear message); `--force` skips that. `--dry-run` reads the files and reports *would create / would update* without changing anything; it doesn't validate (the server does that on the real `PUT`). Nothing is deleted by `deploy`.
- **Run:** without `--wait` it prints the execution id. `--wait` (with `--timeout`) prints status and the items of the last node. `--input <file|->` is a JSON object (one item) or an array.
- **Output:** tables for lists, `--json` prints the API answer; errors go to stderr.
- **Exit codes:** 0 done; 1 the run of `gview-pipe run --wait` ended in `error`; 2 wrong call or an answer of the server other than success (`401`, `404`, `422` with the list of problems, `429`).
- `PipeCliApp.RunAsync` takes the `HttpClient`, the streams and the environment as arguments, so the tests run it against the real API on a test server.

## Consequences

- No profiles or `login` command: one server per call. Profiles can be added without changing the commands.
- Deleting many workflows (`--delete-missing`) and exporting a whole instance are not part of this; the former is risky, the latter belongs with Git export of workflow versions.
